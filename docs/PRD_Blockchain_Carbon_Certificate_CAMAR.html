1. Latar Belakang & Rumusan Masalah

1.1 Konteks Proyek CAMAR

Platform CAMAR dirancang untuk menjembatani penyedia proyek penyerapan karbon (Seller) dengan pembeli emisi (Buyer). Saat ini, CAMAR telah dilengkapi alur pemesanan lengkap: penghitungan emisi via kalkulator, checkout via Midtrans payment gateway, verifikasi transaksi oleh Auditor Pemerintah, hingga penerbitan nomor sertifikat internal (CAMAR-CERT-YYYYMMDD-XXXXXX) yang dapat dicetak oleh Buyer.

1.2 Permasalahan yang Dihadapi (Problem Statement)

  • Kerapuhan Basis Data Terpusat (Centralized DB Vulnerability): Penyimpanan sertifikat pada database MySQL tradisional memiliki risiko manipulasi sepihak oleh pengguna dengan hak akses tingkat tinggi.
  • Isu Klaim Ganda (Double Counting): Sertifikat konvensional berformat PDF tanpa bukti otentikasi on-chain rentan disalahgunakan atau diklaim berulang kali pada audit kepatuhan lingkungan yang berbeda.
  • Ketiadaan Verifikasi Publik Mandiri: Publik, akademisi, atau auditor eksternal tidak memiliki akses independen untuk mengonfirmasi keaslian sertifikat tanpa mendaftar ke platform CAMAR.

1.3 Solusi yang Diajukan

Membangun lapisan verifikasi berbasis Smart Contract di jaringan Polygon Amoy Testnet. Setiap sertifikat yang diterbitkan akan dihitung sidik jari digitalnya (SHA-256) dan dicetak sebagai Soulbound Token (SBT). Sertifikat dilengkapi QR Code dinamis menuju halaman verifikasi publik yang tersinkronisasi langsung dengan Block Explorer (Polygonscan).

2. Arsitektur Sistem (Opsi C: Hybrid Worker)

Pola Arsitektur: Laravel bertindak sebagai pengatur alur transaksi, antrean, dan database lokal, sedangkan worker mandiri berbasis ethers.js mengeksekusi penandatanganan transaksi dan interaksi smart contract secara asinkron (Gasless bagi Buyer).
Tahapan Alur Mekanisme Kerja & Integrasi
1. Approval & Hashing Auditor menyetujui transaksi di Admin Panel. Laravel men-generate nomor sertifikat dan menghitung SHA-256 hash dari data kanonikal sertifikat.
2. Panggilan Worker Laravel memicu skrip issue-certificate.js (via Process::run atau Queue Job) dengan membawa data pesanan dan hash dokumen.
3. Eksekusi On-Chain Worker menandatangani transaksi menggunakan Private Key sistem dan memanggil fungsi issueCertificate() pada Smart Contract Polygon Amoy.
4. Konfirmasi & Penyimpanan Jaringan mengembalikan Transaction Hash (TxHash) & Token ID. Laravel memperbarui record transaksi di tabel orders.
5. Verifikasi Publik Buyer menerima sertifikat berstempel on-chain dengan QR Code dinamis yang langsung dapat dipindai oleh pihak luar.

3. Spesifikasi Basis Data (Database Schema)

Tabel orders ditambahkan kolom metadata blockchain untuk menjamin integritas dan rekam jejak:

Nama Kolom Tipe Data Fungsi & Deskripsi
certificate_hash VARCHAR(64), Nullable Sidik jari digital dokumen (SHA-256) untuk validasi integritas anti-manipulasi.
blockchain_network VARCHAR(50), Nullable Nama jaringan blockchain (Default: Polygon Amoy Testnet).
contract_address VARCHAR(42), Nullable Alamat kontrak pintar (Smart Contract) yang digunakan pada saat penerbitan.
blockchain_tx_hash VARCHAR(66), Nullable Hash transaksi unik dari jaringan Polygon sebagai bukti on-chain permanen.
blockchain_token_id BIGINT UNSIGNED, Nullable ID token unik on-chain (Nomor urut NFT/Soulbound Token).
blockchain_status ENUM('unminted','pending','minted','failed') Status sinkronisasi blockchain (Default: unminted).
blockchain_minted_at TIMESTAMP, Nullable Waktu persis konfirmasi blok transaksi di jaringan blockchain.

4. Rincian Kebutuhan Fungsional (Functional Requirements)

  • FR-1 (Smart Contract Soulbound):
    • Ditulis dalam bahasa Solidity (CamarCarbonCertificate.sol) berbasis standar ERC-721.
    • Fungsi issueCertificate() mencatat: nomor sertifikat, alamat penerima, tonase CO2, hash dokumen, dan waktu penerbitan.
    • Fungsi transfer dinonaktifkan (Soulbound) sehingga token tidak dapat diperjualbelikan kembali di secondary market.
  • FR-2 (Node.js Worker Bridge):
    • Berada pada direktori blockchain/scripts/issue-certificate.js.
    • Menghubungkan aplikasi ke RPC Node Polygon Amoy menggunakan pustaka ethers.js v6.
    • Mengembalikan keluaran terstruktur berformat JSON (status, tx_hash, token_id, gas_used).
  • FR-3 (Modul Penerbitan di Laravel):
    • Terintegrasi pada aksi TransactionManagementController@update saat status diubah menjadi completed.
    • Mencatat seluruh rekam jejak penerbitan ke tabel admin_activity_logs.
  • FR-4 (Pembaruan Template Sertifikat Blade):
    • Memperkaya tampilan resources/views/main_page/dashboard-buyer/certificate.blade.php dengan badge "Verified on Polygon Blockchain".
    • Menampilkan TxHash, SHA-256 Hash, serta Dynamic QR Code verifikasi publik.
  • FR-5 (Portal Verifikasi Publik):
    • Endpoint publik /verify/certificate/{code} yang dapat diakses tanpa autentikasi.
    • Mendeteksi manipulasi data lokal (Tamper-evident system).

5. Skenario Pengujian untuk Laporan Skripsi (Bab 4)

Materi Pengujian Akademis:
  1. Pengujian Fungsional (Black-box): Memvalidasi seluruh skenario operasional dari pembayaran hingga sertifikat berhasil di-mint.
  2. Pengujian Integritas Dokumen (Tamper-evident Test): Memanipulasi nilai data transaksi langsung pada database MySQL, lalu membuktikan bahwa portal verifikasi berhasil mendeteksi anomali ketidakcocokan hash dengan blockchain.
  3. Pengujian Kinerja & Gas Consumption: Mengukur waktu respon signing transaksi, durasi konfirmasi blok Polygon (2–4 detik), dan kebutuhan gas fee.
